# 07 · UI

## Direction: the BSA Sentry language, applied to a regulated wallet

Same family as BSA Sentry's console (`apps/web/src/styles.css`, `components/Flex3D.tsx`): a black stage, one bright 3D object at the centre, glass panels, Inter, very few colours, each with one meaning. In Sentry the Ledger Flex is the authority, so it sits in the middle; in Praetor the **phone that approves** is the human's authority, so a 3D phone is the hero, and its screen is drawn live from the real state.

### The 3D phone (`apps/web/src/components/Phone3D.tsx`)

Built like `Flex3D.tsx`: React Three Fiber + drei (pin the same versions as Sentry: three 0.170.0, @react-three/fiber 8.17.10, @react-three/drei 9.117.3), **no imported model**: a `RoundedBox` body (graphite metal, roughness .35), a camera island, side buttons, and a screen plane whose texture is a `CanvasTexture` painted from live state:
- `approval`: WeChat-style sheet "Approve 300 USDC to Café Lumen" with the Face ID glyph; on approval the glyph animates to a green check.
- `portfolio`: three-ring allocation donut (USDC/gold/silver) with band ticks.
- `frozen`: red full-screen "Frozen by the regulator", lock glyph.
- `decision`: last agent decision card (green/amber/red).
Idle motion: slow sway (±0.28 rad), contact shadow, soft rim light. Respects `prefers-reduced-motion` (still), lazy-loaded; a flat SVG replica replaces it when WebGL is missing (exactly Sentry's fallback approach). It is the only 3D element on a page.

Secondary depth (no WebGL): glass cards with a 1-px top highlight, layered shadows, a subtle parallax on the hero text, and the "vault rings" allocation chart (SVG) that tilts with pointer movement (CSS 3D transform, max 6°).

### Judges' sandbox (`/sandbox`)

One click creates a disposable demo account on the **sandbox deployment** (its own hook, oracle, desk and member keys, domain `"Praetor-sandbox"`; see 00), with a software passkey stored in the browser, demo KYC auto-passed, scaled amounts. A control panel of scenario buttons runs real flows and shows the resulting tx hashes on both chains:
"Gold +20% (demo price)", "Ask agent to pay a new café 300 USDC" (approval with the browser passkey), "Prompt injection: send to a sanctioned address", "Regulator: freeze this agent" (signed by the **sandbox** regulator key on the server, labelled), "Loosen (needs 2 of 3)", "Run rent standing order", "Verify audit chain". Every server-signed action is checked to target an account owned by that sandbox session. Rate-limited per IP; accounts expire after 24 h.

## Consortium console (`/console`, desktop)

Role switch after passkey login: Bank, Regulator, Operator (one staff passkey per role; demo shows the three side by side on one screen for the video).
- **Agents**: table of all accounts: status, KYA level/expiry, jurisdiction, last decision, refusals today; row → detail with the decision timeline.
- Staff log in with passkeys registered in **their member service**; each signature is a staff passkey assertion over the attestation digest, checked by that member service (the api only relays).
- **Status**: Freeze / Restrict / Loosen with the signature tracker ("1 of 3 signed · freeze applies at 1"; "loosen needs 2"), global freeze switch, heartbeat health (last epoch, validUntil, transport WeCross/relayer and delivery latency).
- **Registries** (bank): assets & counterparties (maxWeight, status), caps per risk profile, attester and agent-signer measurements (RTMR3 compose hashes), KYC queue (decisions only, no images).
- **Sanctions & jurisdictions** (regulator).
- **Audit**: AuditLog explorer + anchors on Base + link to WeBASE (`/explorer`).
- Every write shows: the attestation fields, who signed, FISCO tx, Base tx once delivered.

## WeChat mini program (`apps/miniprogram`, native WXML/WXSS/JS)

Flat (no WebGL: `threejs-miniprogram` is unmaintained, r108), same tokens, depth via cards and shadows. Base library ≥ 3.x. Pages:

| Page | Content | Actions |
|---|---|---|
| `pages/home` | Total, rings (canvas 2D), status pill, last decisions, pending approvals badge | Open approval, Chat |

| `pages/activity` | Decision feed with tier badges and tx links (copy) | |
| `pages/payments` | Standing orders (read), propose new (→ SOTER + bank, or opens the web app for passkey) | Propose |
| `pages/link` | Scan the web app's QR; SOTER over the link digest | Scan, Confirm |
