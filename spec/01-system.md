## Keys: who holds what

| Key | Type | Where | Can do | Cannot do |
|---|---|---|---|---|
| Owner passkeys (≤ 4 per account) | P-256 | User's devices (synced passkeys) | Validate owner userOps (`execute`, module calls), sign `Tier2Approval` / `OwnerAction` | Anything without the bank for T3 loosening; any ERC-1271 signature |
| SOTER key | RSA-2048 | Phone TEE, behind WeChat | Sign `resultJSON` over our challenge | Be verified on-chain directly (public key not exposed) |
| Agent key | secp256k1 | agent-signer TEE (`getKey("praetor/agent/<account>")`) | Validate `execute` userOps for its account | Change rules, modules, keys; act outside the hook |
| Attester key | secp256k1 | soter-attester TEE (`getKey("praetor/attester")`) | Sign `SoterApproval` after Tencent says `is_ok` and the binding matches | Approve without a fresh SOTER signature from the bound phone |
| Member FISCO keys | secp256k1 (SM2 in Guomi profile) | bank / regulator / operator services | Send FISCO transactions | Anything on Base |
| Member Base signer keys | secp256k1 | bank / regulator / operator services | Sign attestations the hook accepts | Exceed their threshold (1 to tighten, 2 to loosen) |
| Bundler EOA | secp256k1 | bundler | Submit `handleOps` and plain txs, pay gas | Forge any user or member signature |
| Paymaster signer | secp256k1 | bundler | Sponsor gas for registered accounts | Move funds |
| Oracle feeder | secp256k1 | oracle-feeder | Push prices (bounded by max deviation per update) | Trade |
| Desk operator / token agent | secp256k1 | bank-service | Register identities, freeze tokens, operate the desk. **ERC-3643 agent role can force-transfer or burn tXAU/tXAG of any holder** (regulatory recovery power of the standard; outside the hook, listed as a known risk) | Move USDC; trigger desk swaps for others |
| Payout partner | secp256k1 | payout-partner | Withdraw from PayoutRail, confirm settlements | Pull from wallets |
| WeCross router account | secp256k1 | wecross router (Base side) | Call WeCrossProxy | Forge attestations |

All non-TEE keys live in `.env` (git-ignored), one variable per key, generated by `scripts/keys/generate.ts` in **Phase 0** (separate key sets for local, live and sandbox); the addresses that need Base Sepolia ETH are printed and funded by the human at the Phase 0 stop. Prod: the same names in the server's `.env` (600). TEE keys never exist outside the enclave.

## Trust model

- **Trusted for safety**: the hook's code (on-chain, Slither + fuzz + invariants), member keys within their thresholds, the owner's passkey, the bank-approved TEE measurements (agent signer, attester), Tencent's `verify_signature` answer (unsigned `is_ok`, accepted by decision), WebAuthn.sol + the P-256 precompile.
- **Untrusted** (can delay or withhold, never forge): backend API, MCP server, LLM, scheduler, bundler, bridge relayer, WeCross router, oracle feeder within its deviation bound, WeBASE.
- **Fail-safe**: silence ⇒ heartbeat expires ⇒ the hook treats the agent as RESTRICTED (no autonomous action). Stale prices ⇒ no rebalancing. Unknown target ⇒ refused.
- Residual risks (own them in the self-assessment): a compromised agent TEE, or a compromised **mcp** (the only service allowed to ask the agent signer to sign), acts inside the T1 mandate; a compromised **attester key** can sign SOTER approvals for every SOTER-enabled account (binding and counter are public), so it can approve T2 payments up to each account's hard cap and bank caps until any one member deactivates it; the bank's ERC-3643 agent key can move metal tokens; the team runs all consortium members in the demo; tokens are unbacked; payouts are mocked.

## Invariants (tests must prove each; numbering used across the spec)

| # | Invariant | Proved by |
|---|---|---|
| I1 | Every execution of a Praetor account passes `MandateHook` (execute, executeFromExecutor, module management, fallback). Safe native owners cannot execute. | Foundry fork tests on real Safe7579: `execTransaction` reverts; install/uninstall without owner action revert |
| I2 | Default deny: any target/selector not explicitly modelled is refused | Fuzz on random targets/selectors |
| I3 | A consortium message is accepted only with valid member signatures, nonce > last, before its deadline; tightening needs 1, loosening 2 | Unit + fuzz on signer sets, replay tests |
| I4 | No heartbeat before expiry ⇒ no autonomous action | Time-warp tests |
| I5 | A human approval is bound to one `callHash`, single use, expiring, with a fresh nonce | Unit + replay tests |
| I6 | SOTER counter strictly increases per binding; the binding must match the account's | Unit + replay with lower/equal counter |
| I7 | The agent key can only send `execute` calls; it can never change rules, keys or modules | Validator tests |
| I8 | Effective limit = min(policy, bank caps). Bank caps can never be exceeded, even with T2/T3 | Invariant test over random call sequences |
| I9 | KYC data never leaves the bank service; MCP and agent never receive PII | Service tests that grep responses and logs for the seeded PII |
| I10 | Secrets never in git; TEE keys never leave the enclave | gitleaks in CI; TEE API has no export route |
| I11 | Refusal reasons in `RefusalLog` are computed by the hook's `check()` | Unit test: logger cannot inject a reason |
| I12 | All arithmetic checked; overflow ⇒ refuse | Fuzz with extreme values |
| I13 | Prod config refuses simulator attestations and debug-mode TEEs | Config test |
| I14 | While FROZEN, no transaction moves value out of the account (payments, swaps, payouts, standing orders) | Invariant test |
| I15 | Bands: a rebalance never ends with an asset outside its band unless it moved closer to target | Fuzz on prices and amounts |
| I16 | No signature path outside the hook: the account never returns a valid ERC-1271 signature; Safe `signedMessages` unreachable | Fork tests: USDC `permit` and `transferWithAuthorization` with agent key, passkey, empty signature all fail |
| I17 | Every non-view selector of the deployed Safe7579 adapter is either hook-wrapped or unreachable by our validators | Fork test enumerating the adapter ABI |
| I18 | A consortium message can't block future messages: nonce/epoch must equal stored + 1 | Unit test: nonce 2⁶⁴−1 refused |
| I19 | No personal data on Base: only addresses, amounts and hashes (no names, labels, references, invoices, KYC fields) | e2e: scan every Base tx calldata and event of the live suite for the seeded names, labels and references |
