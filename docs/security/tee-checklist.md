# TEE deployment checklist

Applied to both Phala Cloud CVMs (Intel TDX, dstack): **agent-signer** (one secp256k1 agent key per account, derived with `getKey("praetor/agent/<account>/v<n>", "agent", "secp256k1")`) and **soter-attester** (one key, `getKey("praetor/soter-attester/v1", "attester", "secp256k1")`). The list is spec 08's. For each item: how it is checked, what the code enforces today (local stack on the dstack simulator), and its status. The deployment itself is a Phase C step with the human (`docs/DEPLOY.md`, `docs/MANUAL.md` step 2); results go in the last column then.

| 1 | Production (non-debug) CVM | The CVM's attestation report: the TD attributes must not have the DEBUG bit; the Phala dashboard shows the CVM as production | The bank verifies quotes through Phala's verifier (`https://cloud-api.phala.com/api/v1/attestations/verify`) and accepts only `verified: true` (`services/bank/src/attestation.ts`, `phalaVerifier`). It does **not** parse the TD attributes itself, so a debug CVM is refused only if Phala's verifier refuses it | Both CVMs run the production OS image since 2026-10-20 (`--no-dev-os`, D106); the DEBUG bit is still left to Phala's verifier. | 7 | No key export route | List the routes of both services; no response carries key material | agent-signer routes: `/health`, `/v1/info`, and under `/v1/agents/:account/`: `address`, `attest`, `sign-userop`, `sign-weid`; soter-attester routes: `/health`, `/v1/info`, `/v1/attest`, `/v1/soter/approve`. Responses carry addresses, public keys, quotes and signatures only. Test: `services/agent-signer/test/signer.test.ts` ("never returns key material") | Enforced |

## What the simulator does not prove

On the local stack the measurement is `keccak256(RTMR3)` of a simulator quote and the mode comes from our own configuration (nothing in a simulator quote says "simulator", V5). The tests prove the binding of key and nonce, the allowlist logic against a scripted verifier and the refusal paths; they do not prove Phala's verifier or a real TDX quote. If the verify API is unreachable or its answer differs in Phase C, the fallback of `docs/MANUAL.md` step 2 applies and is stated plainly. On 2026-10-20 its answer no longer carried `app_info.compose_hash`: the bank now reads the compose hash that dstack writes into the verified quote's MRCONFIGID (commit `9056861`), and the attester's quote passed.
